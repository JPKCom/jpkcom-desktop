Writing pages

Plain HTML files, one folder per language. The Reader shows them natively in a window — no iframe, no scripts.

The markup

The Reader looks for the content with the rules in config.reader.rules. The example site uses one rule for everything below site/content/: the content is the first main article, article or main, the title its h1, the lead a paragraph with the class lead.

<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<title>Page title | Site name</title>
<link rel="alternate" hreflang="de" href="../de/page.html">
<link rel="stylesheet" href="../content.css">
</head>
<body>
<main>
<article>
<h1>Page title</h1>
<p class="lead">One or two sentences about the page.</p>
<h2 id="part">A section</h2>
<p>Text, <a href="other.html">links</a>, lists, tables, figures …</p>
</article>
</main>
</body>
</html>

What to keep in mind

  • Title: the window shows the part of <title> before “ | ”, else the h1.
  • Languages: <html lang> sets the language of the text; <link rel="alternate" hreflang> tells the Reader which page to show after a language switch.
  • Links: relative links to other pages open in the same window; links to other sites open in a new tab; #anchors scroll.
  • Allowed: text, headings, lists, tables, figures and pictures, details, pre and code, audio and video with controls.
  • Removed: scripts, styles and style attributes, forms, iframes, event handlers. The page's own stylesheet only matters when it is opened outside the desktop.
  • Classes get the prefix c-, so no class of a page can change the desktop. Style them with .reader-page .c-name in a stylesheet of your own.

For the terminal

A Markdown twin of a page (about.md next to about.html) can be listed under files in site/apps.js; the terminal shows it with cat about.
